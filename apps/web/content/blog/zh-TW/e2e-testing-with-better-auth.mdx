## 簡要概述

您需要產生一個有效的工作階段權杖並將其儲存為 Cookie。這允許您的端到端測試存取需要身分驗證的路由，而無需手動登入。此方法適用於使用帳號密碼或 OAuth 的身分驗證。

> GitHub 程式碼庫：[nelsonlaidev/e2e-testing-with-better-auth](https://github.com/nelsonlaidev/e2e-testing-with-better-auth)

## 前言

在本指南中，我們將使用 [Playwright](https://playwright.dev/) 作為我們的端到端測試框架，但這些概念同樣適用於其他框架，如 [Cypress](https://www.cypress.io/)。

為了簡化說明，本範例採用帳號密碼驗證；相同原則也適用於 OAuth 提供者。

此外，我們使用 SQLite 資料庫進行示範。請根據您的設定調整資料庫操作（**例如，資料表名稱、欄位型別**）。

## 產生工作階段權杖

為了模擬已通過驗證的工作階段，我們需要使用 `BETTER_AUTH_SECRET` 產生一個簽章的工作階段權杖。此權杖將用於工作階段 Cookie 中。

```ts
import crypto from 'node:crypto'

export const TEST_USER = {
  name: 'Test User',
  email: 'test@example.com',
  sessionToken: '00000000000000000000000000000000',
  accountId: '000',
}

const signature = crypto
  .createHmac('sha256', process.env.BETTER_AUTH_SECRET!)
  .update(TEST_USER.sessionToken)
  .digest('base64')
const signedValue = `${TEST_USER.sessionToken}.${signature}`
```

## 插入測試資料

我們希望重複使用固定的測試使用者，避免在測試期間建立多個使用者。如果測試使用者、帳戶和工作階段尚未存在，則將其插入資料庫。為簡單起見，我們使用 `0` 作為所有主鍵的唯一 ID。

```ts
import { db } from '@/lib/db'

const TEST_UNIQUE_ID = '0'

const now = new Date().getTime()
const expiresAt = new Date(Date.now() + 7 * 24 * 60 * 60 * 1000).getTime() // 7 days

const transaction = db.transaction(() => {
  db.prepare(
    `
      INSERT OR IGNORE INTO user (
        id, name, email, emailVerified, createdAt, updatedAt
      ) VALUES (?, ?, ?, ?, ?, ?)
    `,
  ).run(TEST_UNIQUE_ID, TEST_USER.name, TEST_USER.email, 0, now, now)

  db.prepare(
    `
      INSERT OR IGNORE INTO account (
        id, accountId, providerId, userId, password, createdAt, updatedAt
      ) VALUES (?, ?, ?, ?, ?, ?, ?)
    `,
  ).run(TEST_UNIQUE_ID, TEST_USER.accountId, 'credential', TEST_UNIQUE_ID, 'password_hash', now, now)

  db.prepare(
    `
      INSERT INTO session (
        id, token, userId, expiresAt, createdAt, updatedAt
      ) VALUES (?, ?, ?, ?, ?, ?)
      ON CONFLICT(token) DO UPDATE SET
      expiresAt = excluded.expiresAt,
      updatedAt = excluded.updatedAt
    `,
  ).run(TEST_UNIQUE_ID, TEST_USER.sessionToken, TEST_UNIQUE_ID, expiresAt, now, now)
})

transaction()
```

## 儲存工作階段

將簽章的權杖儲存為 JSON 檔案中的 Cookie，以便在測試框架中使用。不要忘記對 Cookie 值進行 `encodeURIComponent{:.entity.name.function}` 編碼。

```ts
import fs from 'node:fs/promises'

const cookieObject = {
  name: 'better-auth.session_token',
  value: encodeURIComponent(signedValue), // [!code highlight]
  domain: 'localhost',
  path: '/',
  httpOnly: true,
  secure: false,
  sameSite: 'Lax',
  expires: Math.round(expiresAt / 1000),
}

await fs.mkdir('.auth', { recursive: true })
await fs.writeFile('.auth/auth.json', JSON.stringify({ cookies: [cookieObject], origins: [] }, null, 2))
```

## 在測試中使用工作階段

在您的端到端測試中載入儲存的工作階段，以存取受保護的路由，而無需登入。以下範例使用 Playwright，但這可以適應任何支援 Cookie 注入的測試函式庫（例如，Cypress）。

```ts title='playwright.config.ts'
export default defineConfig({
  // ...
  projects: [
    { name: 'setup', testMatch: /global\.setup\.ts/, teardown: 'teardown' }, // [!code highlight]

    { name: 'teardown', testMatch: /global\.teardown\.ts/ }, // [!code highlight]

    {
      name: 'chromium',
      use: {
        ...devices['Desktop Chrome'],
        storageState: '.auth/auth.json', // [!code highlight]
      },
      dependencies: ['setup'], // [!code highlight]
    },
  ],
})
```
